# 站点开发约定

本文件适用于 `site/`，与仓库根目录的 `AGENTS.md` 一起生效。回复用户时称呼 yume。

## 修改前

- 修改路由、内容解析或展示行为前，阅读 `docs/features.md` 中对应部分；完成后同步更新该文档。
- 依赖、命令及组件配置以 `package.json`、`components.json` 和 `next.config.ts` 为准。优先复用已安装组件。

## 视觉与交互

- 全站保持 Magic UI 星轨视觉语言；布局和颜色在 `app/globals.css` 的语义令牌中统一管理，组件适配白天与黑夜两种主题。
- 白天默认使用白色页面、侧栏和卡片，强调色用于选中态与装饰；黑夜保持深色星空。主题按钮显示当前状态，提示说明切换目标。
- 导航与操作图标使用配置中的 Lucide SVG，同类图标统一尺寸与线宽。字符星形仅用于装饰。
- 保留主题导航 Git、Agent、爬虫（小说爬虫、动漫爬虫）及侧栏底部小说资源。侧栏收起后仍可展开；移动端导航独立处理。
- 动效尊重减少动态效果偏好，正文阅读优先保证可读性；装饰不进入无障碍阅读顺序。交互元素保留键盘操作及明确标签。

## 内容与路由

- 内容目录与笔记维护遵循根目录约定，站点通过 `lib/` 的读取和解析逻辑展示内容。
- Markdown 元数据单独展示，正文移除 frontmatter 与重复的开头标题，每篇文章只显示一次主标题。
- 本地链接通过现有路径工具处理 basePath、中文编码与相对路径；验证笔记、源码和附件链接。
- 生产环境保持静态导出。开发期关闭 `output: export` 是为规避 Next 开发服务器的中文参数匹配问题，修改时分别验证开发与生产行为。
- 源码扫描须区分代码与媒体；动漫视频的 `.ts` 后缀可能是 MPEG-TS，而非 TypeScript。遇到超大文件先确认类型。

## 验证与交付

- 在 `site/` 运行 `npx tsc --noEmit`。根据改动运行 `scripts/check-magic-theme.ps1`、`check-note-routes.ps1`、`check-source-links.ps1` 或 `node scripts/check-note-content.mjs`，先检查脚本参数。
- 样式和交互改动验证白天、黑夜及移动端；确认无横向溢出、主题切换与侧栏操作正常。
- 路由或导出改动还需运行生产构建；若被阻塞，明确报告原因，区分已通过的检查与未完成的检查。
- 本地启动前确认目标端口，复用相关开发服务；临时截图与日志放在仓库根目录 `temp/`，交付时说明实际验证结果。
