# 从0开始的异世界 · 单季直链下载

## Summary

聚合播放站 dm84.tv 上《Re：从零开始的异世界生活》第一季（25 集）的视频下载脚本，是这套 hhjx 播放器解析链路的**最小纯净范例**：一条线路、全是单文件 mp4 直链、请求头固定，没有多线路分支。讲透"播放页 → 解析接口 → 真实直链 → 下载落地"整条链路最省事；[进击的巨人那篇](进击的巨人-多线路下载策略.md) 则是在这条链路之上处理 18 个季 key 线路分化后的进阶版。

成果：`videos/第01集.mp4 … 第25集.mp4` 全部下齐。

- 源码：[scratch.js](../../../../动漫/从0开始的异世界/scratch.js)（解析）、[downloadVideo.js](../../../../动漫/从0开始的异世界/downloadVideo.js)（下载）
- 项目自述：[README.md](../../../../动漫/从0开始的异世界/README.md)
- 技术栈：Node.js + axios（HTTP）+ cheerio（DOM 解析）

## Notes

### 一、整条链路只做一件事：把"播放器地址"换成"视频地址"

dm84.tv 不直接给视频地址，页面里嵌的是第三方播放器（hhjx，域名为 `*.hhplayer.com`）。下载分两步、两个脚本：

```text
scratch.js  ──抓每集播放页、提取播放器 iframe──>  players.json
downloadVideo.js ──逐集现取现解析、下载──>  videos/第XX集.mp4
```

拆开的收益：解析（要发一堆页面请求、易被反爬打断）和下载（慢、易被网络波动打断）各自独立重跑，`players.json` 一次抓好后反复用。

### 二、players.json 是怎么生成的（scratch.js）

1. 详情页 `/v/109.html` 里用 cheerio 扫 `<a>`，正则 `^/p/109-1-(\d+)\.html$` 只留**线路 1** 的第 1–25 集（`109` 是本剧 id，`1` 是线路号，末段是集数）。
2. 逐集打开分集页，在 `<iframe>` 里找 src 含 `hhplayer` / `player` / `url=` 的那个，得到播放器地址 `iframeUrl`，并从其 query 里取出 `playerToken`（`?url=` 参数）。
3. 每集结果 `{ episode, pageUrl, iframeUrl, player }` 写进 `players.json`；抓失败的集记 `error`，后续下载时被过滤掉。

> 脚本请求头带了一个站点会话 cookie（`PHPSESSID` 等）。这个值会过期，笔记里不记录具体值——失效时从浏览器 DevTools 整段重拷即可。

### 三、核心：bootstrap → /api/parse → 直链（downloadVideo.js）

这是整套方法最该记住的一段，[进击的巨人篇](进击的巨人-多线路下载策略.md) 完全复用同一链路：

```text
打开 iframeUrl 页
   └─ 正则抓 window.__HHJX_BOOTSTRAP__={...}   得到 { url, t, key }（有时效，必须现取现用）
POST <播放器 origin>/api/parse   body={ url, t, key }   （bootstrap.act===99 时附带 act）
   └─ 返回 { code:200, url }    这个 url 就是真实视频地址
把 http:// 升级为 https:// 后，流式下载
```

关键点：

- **引导参数有时效**：`__HHJX_BOOTSTRAP__` 里的 `t`/`key` 是签了名的临时凭据，抓下来要立刻用，不能缓存到 `players.json` 延后使用——所以解析动作放在下载脚本里、紧挨着下载，而不是在 scratch.js 阶段。
- **`/api/parse` 的 Referer/Origin 指向播放器域**（`iframeUrl` 本身），不是 dm84——这是"模拟播放器发起解析请求"，和后面取视频文件的 Referer 是两回事。
- 本剧解析出的地址都是腾讯 `om.tc.qq.com` 的 mp4 直链，单文件，一次 GET 到底。

### 四、下载落地：三防

`downloadVideo.js` 的健壮性做法，进击篇沿用并加强了：

- **`.part` 临时文件 + 完整性校验**：先下成 `xxx.mp4.part`，落地字节数与响应 `content-length` 一致才 `rename` 成 `.mp4`；中断/出错删除 `.part`。这样 `fs.existsSync(output)` 判断"已存在"时，一定等于"完整"。
- **断点续跑**：主循环开头 `existsSync(output)` 命中即跳过，不发解析请求。
- **失败重试**：`withRetry(fn, 3)` 对"解析 + 下载"整体做最多 3 次指数退避（3s/6s/9s），吸收 TLS 断连、代理超时（本地代理出口偶发 `ETIMEDOUT`）等瞬时网络错误。集与集之间再 `sleep(500)` 节流。

### 五、命令

```powershell
npm install
node scratch.js            # 抓 players.json（一般只跑一次）
node downloadVideo.js      # 下载全部
node downloadVideo.js 1 10 # 只下第 1–10 集（起始集 结束集）
```

命令行区间参数是本脚本唯一的筛选手段；进击篇因为有 18 个 key，改成了按 key/组名分流（见那篇的 `catalog.js` + `resolveSeasonKeys`）。

### 六、请求头为什么是"带 Referer"

本剧所有集取视频文件时都带 `Referer: https://dm84.tv/`（`PAGE_HEADERS`）即可 200/206。**这不是普适规律**：同一站点另一部《进击的巨人》里，`xhscdn`、`photovideo.photo.qq.com` 这类 CDN 恰恰相反——**带任何外部 Referer 会被拒**（403 或伪装成 404），必须不带 Referer 才通。判别方法见 [进击的巨人篇](进击的巨人-多线路下载策略.md)。
