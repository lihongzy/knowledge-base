# 进击的巨人 · 多线路下载策略

## Summary

同一套 dm84.tv / hhjx 解析链路（基础原理见 [从0开始的异世界篇](从0开始的异世界-单季直链下载.md)），但本剧有 **18 个季 key**（日配主线六季、国语四季、剧场版/OAD/外传/衍生八部），它们解析出来的地址**性质天差地别**：有单文件 mp4、有把 MPEG-TS 套进假 PNG 头里的 HLS 分片、还有干脆拿不到的死线路。

核心设计：用一个**显式策略表 `SEASON_STRATEGY`** 为每个 key 钉死下载方式，运行时**不探测、不降级**——链路与表不符就报错交人改表，而不是偷偷换方式。这是本项目相对 [从0 那篇](从0开始的异世界-单季直链下载.md) 的唯一但关键的区别。

成果（2026-10 实测，按 `videos/` 落地）：日配主线 s1–s4/final2 全下齐、finale 已下前篇、三部剧场版已下；国语四季与 OAD/LOST GIRLS/巨人中学/编年史/外传为死线路。

- 源码：[scratch.js](../../../../动漫/进击的巨人/scratch.js)、[downloadVideo.js](../../../../动漫/进击的巨人/downloadVideo.js)、[catalog.js](../../../../动漫/进击的巨人/catalog.js)
- 项目自述（含 18 行可用性对照表）：[README.md](../../../../动漫/进击的巨人/README.md)
- 额外依赖：`hls` 类线路需本地 **ffmpeg**（在 PATH 中）

## Notes

### 一、catalog.js：条目与分组的单一来源

[catalog.js](../../../../动漫/进击的巨人/catalog.js) 导出 `CATALOG`（18 个 key → `{key,group,name,detailUrl,line:1}`）和 `GROUPS`（`main`/`cn`/`extra`）。`scratch.js`（解析）与 `downloadVideo.js`（下载）共用它，避免两处各写一份清单而漂移。

`downloadVideo.js` 的 `resolveSeasonKeys(argv)` 把命令行参数展开成 key 集合：`all` → 全部；组名 → 该组 keys；单个 key → 自身；识别不了 → 打印"忽略"。**无参数 = 不过滤下载全部；有参数但全没匹配 = 空集合、什么都不下**（这是踩过"参数没识别结果回退成全下"的坑后定的语义）。

### 二、SEASON_STRATEGY：把"这个 key 该怎么下"写死

[downloadVideo.js](../../../../动漫/进击的巨人/downloadVideo.js) 里每个 seasonKey 对应 `{ kind, headers?, note }`，`kind` 三选一。主循环按 `kind` 分流：

| kind | 数量 | 处理 | 代表 |
| --- | --- | --- | --- |
| `direct` | 4 | 单文件 mp4，`directHeaders(mode)` 固定该 CDN 能过的那组请求头 | s1（带 Referer）、s4/movie1/movie2（不带 Referer） |
| `hls` | 5 | 播放列表分片下载 → 切假头 → 拼 `.ts` → ffmpeg remux | s2/s3/final2/finale/movie3 |
| `dead` | 9 | 已确认本站拿不到，直接跳过，不发解析请求、不重试 | cn1–cn4、oad、lostgirls、junior、chronicle、sidestory |

设计意图（用户明确要求）：**不搞运行时探测/降级**。方式写死在表里，读表即知每个 key 的命运；`dead` 的 `note` 把"为什么拿不到"也钉死在代码里，跑的时候打印出来。新增季就在表里加一行，不在表里的 key 会被跳过并提示补充。

### 三、direct：Referer 防盗链的两种状态码（最烧脑的一关）

浏览器 `<video>` 请求视频时**不带 referrer**，脚本据此对不同 CDN 固定头：

- **需要带 `Referer: dm84.tv`** 的：`om.tc.qq.com`（s1）。带才对，属于常规白名单。
- **必须不带 Referer**（只发 UA）的：`xhscdn`（s4）带任何外部 Referer 回 **403**；`photovideo.photo.qq.com`（movie1/movie2）更阴——带 Referer 时回 **404 伪装成"资源不存在"**，而不是 403。去掉 Referer 后两者都 200/206，落地是真 MP4（magic `....ftypisom`）。

教训：**Referer 防盗链的拒绝状态码不统一**（403 / 404 都可能），不能只认 403。当初"遇 403 才降级重试"的写法漏掉了 photovideo 的 404；后来索性按 key 写死，不再有"降级"这段逻辑。

> `bytes=0-` 之类 Range 头是浏览器拖进度条产生的分段请求，非协议要求，脚本不带 Range 也回 200。

### 四、hls：分片是套了假 PNG 头的 MPEG-TS

`s2/s3/final2/finale/movie3` 解析回来的是 m3u8 播放列表，但**分片被伪装成图片**（ljcdn 首片报 `image/png`、qpic.cn 报 `image/jpeg`），实为 MPEG-TS。`downloadViaHls` 的处理：

1. 抓播放列表，按行取非 `#` 条目为分片 URL（相对地址用 `new URL(s, videoUrl)` 解析）。
2. **有限并发（CONC=4）下载、按索引保序**回填 `parts[]`，保证 TS 拼接顺序正确；每片 `withRetry` 3 次。
3. `fetchSegmentClean`：分片请求**不带 Referer**（ljcdn 带 Referer 反被 403），拿到字节后用 `findTSOffset` 切掉假头。
4. `findTSOffset`：MPEG-TS 每包 188 字节、以 `0x47` 同步头开头，故找满足 `buf[o]===0x47 && buf[o+188]===0x47 && buf[o+376]===0x47` 的偏移 `o`，从 `o` 起才是真 TS（先在前 4096 字节找，找不到再全文件兜底）。
5. 拼成连续 `.ts` 后 `ffmpeg -c copy -bsf:a aac_adtstoasc -movflags +faststart -f mp4` remux。源已是 H.264/AAC，直接 copy 不转码。
   - **坑**：输出临时文件后缀是 `.part`，ffmpeg 靠扩展名认不出容器，**必须显式 `-f mp4`**。
   - remux 失败时保留拼好的 `.ts`（本身可直接播放），不连累整集白下。

### 五、有效性判定与死线路（dead）

- **有效性**：本地文件 `size >= MIN_VALID_BYTES(1MB)` 且首字节非 `#EXT` 才算完整（`isValidExisting`）；direct 下完再 `looksLikePlaylist` 复查，实为 m3u8 就删掉报错。过小文件或残留 m3u8 文本会被删除重下。
- **一致性校验（不是降级）**：`kind==="hls"` 但 parse 回来的不是播放列表、或 `direct` 下回内容实为 m3u8，**直接抛错**提示"源线路可能已变，请更新 SEASON_STRATEGY"，不自动换方式。
- **dead 的两类根因**，都卡在服务端/源站、客户端改头也救不了：
  - `parse 400`：POST `/api/parse` 时 hhjx 服务器直接拒（cn1–cn4、oad、lostgirls、junior）——该线路源本就不被这个解析器支持。浏览器若能播，用的是另一套播放器线路，需改 scratch.js 抓取时的 `line` 重抓。
  - `分片 404`：播放列表能取到，但分片在源 CDN 已 404（chronicle 在 `rescdn.yishihui.com`、sidestory 在 `kwimgs.com`）——片被删。源恢复后把表里这两行从 `dead` 改回 `hls` 即可。

### 六、实测驱动、只读探测的工作法

这些分类不是猜的，是用一次性探测脚本（`temp-why.js` 等，用完即删）跑出来的：对每个 key 走一遍 `getBootstrap → /api/parse`，看返回的是直链还是 m3u8；对 HLS 只 `GET Range: bytes=0-N` 取首片头部，验状态码、`content-type`、magic 字节——**绝不整片下载**（无 Range 会把 900MB 全拉下来）。据此把 18 个 key 钉进表。
